# GDAL parity

rwarp is checked against GDAL output, component by component. The test
fixtures are generated by scripts in `tests/fixtures/` from a stated GDAL
build, and the tests compare rwarp's results to them.

## What has been checked

| Component | Test data | Result |
|---|---|---|
| `GenImgProjTransformer` | Sentinel-2 B04 | 65536 of 65536 pixels identical to `pixel_extract` |
| `ApproxTransformer` | same | bit-identical to `GDALApproxTransform` |
| `compute_source_window` | GEBCO global, Fiji LCC | matches GDAL's source windows |
| Nearest neighbour | Sentinel-2, IBCSO Mawson | 65536 of 65536 identical to `gdalwarp -r near` |
| Bilinear, cubic, lanczos | GEBCO at about 1:1 | 65536 of 65536 identical |
| Kernel widening, scale estimate | synthetic, 1.5:1 to 4:1, anisotropic, nodata | within 1e-6 relative of gdalwarp |
| Point kernels at any ratio | same, against `-wo XSCALE=1 -wo YSCALE=1` | within 1e-6 relative |
| Average, GDAL box | plus upsampling, overhanging and 30 degree rotated targets | within 1e-6 relative of `-r average` |
| Average, exact footprint | axis-aligned cases against the box; a 45 degree diamond against the analytic mean | within 1e-5 |
| Mode, all `MODE_TIES` | categorical Byte/Int16/Int32/Float32, 4:1 and 2.78:1, nodata, rotation | identical to `-r mode` (26 cases) |
| Nodata, per band and unified, average thresholds | single- and three-band Float32, every method | within 1e-6 relative (30 cases) |
| Rounding, clamping, nodata avoidance, source bounds | Byte/Int16/Int32/Float32 | identical (12 cases) |
| Antimeridian split read | GEBCO, Fiji tile | 70 times fewer source pixels than a naive read |
| Geolocation arrays | synthetic swath, both conventions, curvilinear source and target | coordinates within 1e-6 px; nearest warps identical to `gdalwarp -et 0` |
| Cutline: centre rule, all touched, blend distance | synthetic Float32; edges and vertices through pixel centres, holes, multipolygons, source nodata, every method but mode, 1:1, 2.78:1 and upsampled, 30 degree rotated, LAEA to lon/lat with the cutline in either CRS | within 1e-6 relative of gdalwarp (67 cases; the reprojected ones identical with libproj and proj4rs) |
| Cutline tie rules | GDAL's own rasterizer on centre-tie polygons | identical, except 5 centres on one diagonal edge where GDAL's intercept is a rounding error either side |

The kernel and cutline fixtures use GDAL 3.14.0dev (`739fcf03bf`); the geolocation
fixtures use GDAL 3.8.4.

## Where rwarp deliberately differs

| Behaviour | GDAL | rwarp | Why |
|---|---|---|---|
| Kernel scale estimate in a chunked warp | taken at the top-left of the whole output for every chunk | taken over the window being warped | GDAL's sample points omit the chunk offset; chunked and single-chunk gdalwarp output differ |
| `MODE_TIES` for 32/64-bit and float data | `Min`/`Max` skipped for a value's first occurrence | the 8/16-bit behaviour for every type | the same data should not give different modes by type |
| Geolocation inverse | backmap plus local search | index of all quadrilaterals | same answer on unfolded grids; see [Curvilinear grids](guide/curvilinear.md) |
| Cutline all touched | centre rule plus each boundary line walked pixel to pixel, with tolerances | pixels with any covered area (above 1e-9) | GDAL also burns pixels touched only at a corner (below-right of it), skips edges within 1e-4 of a pixel wall, and burns one column for an edge within 0.01 px of vertical even where the polygon is in the column to its left |
| Cutline centre ties on diagonals | intercept rounding | intercept rounding, computed differently | GDAL keeps 23 and drops 5 of the 28 centres on one 45 degree edge; neither is a rule |
| `Cutline::from_transformer` densification | skipped when `-cblend` is given (unless `GDALWARP_DENSIFY_CUTLINE=YES`) | always | the helper does not know about blending; densifying only makes the transformed cutline more accurate |
| Approximate transformer fallback | retries points slightly off the source with the exact transformer | uses the transformer it is given | keeps the kernel independent of transformer type |

## GDAL issues found along the way

Matching gdalwarp closely turned up behaviour in GDAL itself that looks
unintended: the chunk-offset scale estimate, `MODE_TIES` by data type, the
`MODE_TIES=FIRST` documentation, edge weights above 1 in `average` when a
target pixel overhangs the source, destination nodata avoidance with a float
working type, and two different rounding rules into integer outputs. They
are written up with repros in
[mdsumner/osgeo-upstream](https://github.com/mdsumner/osgeo-upstream/blob/main/notes/2026-10-28-gdalwarp-kernel-findings.md).

The cutline work found more, not yet in that write-up: all-touched burns
pixels the boundary touches only at a corner, and a whole column along an
edge within 0.01 pixels of vertical; centre ties on diagonal edges are
rounding; blend distance dilates the cutline for the area methods instead
of feathering it; and `-cblend` turns off cutline densification.
